Mobile Application Penetration Testing for Android & iOS

Static and dynamic testing of Android and iOS apps, including the backend traffic they depend on, with a report mapped to OWASP MASVS.

Request a Scoping Call

What Gets Tested

A mobile app is two things: code running on a device you do not control, and a backend it talks to. Testing covers both, aligned with OWASP MASVS and the Mobile Application Security Testing Guide (MASTG).

Static analysis

  • Decompiling the app to find hard-coded keys, tokens, and secrets.
  • Reviewing the manifest, exported components, deep links, and permissions.
  • Checking cryptography use and insecure build settings.

Dynamic analysis

  • Runtime testing with Frida and MobSF to observe real behaviour on a device.
  • Traffic interception with Burp Suite, including testing whether certificate pinning can be bypassed.
  • Local storage, logs, clipboard, screenshots, and backups: what sensitive data is left on the device.
  • Root and jailbreak detection, tamper resistance, and WebView issues.
  • Authentication, biometric flows, and session handling.

Backend and API

Every request the app makes is tested for access control and input handling flaws, because that is where the most serious mobile findings usually turn out to be. See API security testing for how that side is covered.

Apps built with Flutter and React Native are in scope too. For a technical example of the depth involved, read how SSL pinning is bypassed in Flutter apps on ARM64.

How the Engagement Works

  1. Scoping call. We agree the assets, user roles, testing window, and rules of engagement, and I send a fixed quote.
  2. Access and authorisation. You provide written permission, test accounts, and any IP allow-listing needed.
  3. Testing. Automated coverage first, then manual testing for the issues scanners cannot find.
  4. Report and walkthrough call. Every finding comes with severity, proof of concept, impact, and a fix your developers can act on.
  5. Free retest. Once you have fixed the findings, I verify them and update the report.

What You Receive

  • An executive summary for management and a technical section for developers.
  • Every finding with a severity rating, proof-of-concept steps, and business impact.
  • Remediation guidance specific to your stack, not generic advice.
  • A walkthrough call with your team.
  • A free retest and an updated report showing which issues are closed.

Frequently Asked Questions

Do you test Android and iOS together?
They are scoped separately because each platform has different device-level checks, though they share the same backend. Testing both is common, and the backend API is not charged twice.
Do you need the source code?
No. Most mobile tests are grey-box: I need an installable build and test accounts. Source code access adds depth but is optional.
Can you test Flutter or React Native apps?
Yes. These frameworks change how traffic interception and pinning work, and I have hands-on experience with Flutter pinning bypass on ARM64.
How long does a mobile app test take?
A single-platform app typically takes 3 to 7 business days of testing plus reporting. Complex apps or both platforms together take longer, confirmed at scoping.
Is a retest included?
Yes. After your team fixes the findings, I verify them and update the report at no extra cost.
